2. 五分钟开始调用（在你的本机）

下列命令在仓库根目录执行。轻量示例只需要Python 3.11以上和httpx，不需要在调用方下载模型或安装PyTorch。已有可用httpx环境可直接使用；新建专用环境只需做一次。

python3 -m venv .venv-client
.venv-client/bin/python -m pip install httpx==0.28.1

export OMNI_INFERENCE_URL='https://u151984-79222bf22ba5.bjb2.seetacloud.com:8443'
export OMNI_INFERENCE_KEY_FILE="$PWD/data/autodl/inference.key"
chmod 600 "$OMNI_INFERENCE_KEY_FILE"

.venv-client/bin/python docs/examples/embeddinggemma_client.py health
.venv-client/bin/python docs/examples/embeddinggemma_client.py probe
.venv-client/bin/python docs/examples/embeddinggemma_client.py text \
  --text '厨房里正在切菜的画面'

默认打印成功、维度、模型与版本等摘要，已校验向量行数、有限值、单位范数。要保存真实向量，把全局选项放在子命令之前；输出文件使用600权限且拒绝覆盖已有文件。

.venv-client/bin/python docs/examples/embeddinggemma_client.py \
  --output /tmp/query-embedding.json text --text '海边日落'

.venv-client/bin/python docs/examples/embeddinggemma_client.py text \
  --input-type document --text '锅中加入番茄与鸡蛋，快速翻炒。' --title '番茄炒蛋'

.venv-client/bin/python docs/examples/embeddinggemma_client.py \
  --dimensions 768 image /absolute/path/photo.jpg

.venv-client/bin/python docs/examples/embeddinggemma_client.py video \
  /absolute/path/frame01.jpg /absolute/path/frame02.jpg

敏感正文建议用 text --text-file /absolute/path/query.txt，避免命令历史记录正文。视频输入是图片帧，MP4须先在调用端解码抽帧。示例脚本支持最多3次仅针对429的尝试，遵守Retry-After并增加随机等待；网络超时不会自动重放。--timeout覆盖排队、HTTP与重试等待，不包括此前本地文件读取、此后结果校验与写文件。

把本地MP4准备成可调用的帧

新增本地抽帧工具默认从短视频均匀取最多8个不同真实帧，按时间排序、保持比例缩至长边最多512像素，再输出JPEG与采样manifest。文件不上传时也能先检查抽帧效果。以下固定依赖组合已在Python3.12环境验证；若第2节的环境使用Python3.11或3.12，可在其中一次安装。其他Python版本请使用已有兼容项目环境或另建Python3.12环境，避免强行混装旧NumPy。

set -e
.venv-client/bin/python -m pip install numpy==1.26.4 opencv-python-headless==4.11.0.86 httpx==0.28.1

# 选择尚不存在的新目录；输入已经下载到本地的短视频片段
.venv-client/bin/python docs/examples/prepare_video_frames.py \
  /absolute/path/short-clip.mp4 \
  --output-dir "$PWD/data/prepared-video/clip001"

# 两位序号文件名会按采样顺序展开；不足8帧时只发送实际帧
.venv-client/bin/python docs/examples/embeddinggemma_client.py video \
  "$PWD/data/prepared-video/clip001"/frame*.jpg

沿用第2节的URL与Key文件变量。manifest记录原视频哈希、帧索引、名义时间、缩放策略和帧哈希；变帧率视频的索引/FPS不保证精确时间戳。长视频先分镜头或短片段。默认8帧只与质量评测的帧数一致，不代表所有预处理完全相同，调整策略后仍需验收召回。

镜像保留与关机规则

2026-10-18核对官方帮助文档：保存成功的自定义镜像不会因源实例关机而丢失，可用于长期留存环境和创建新实例，但不是无条件永久保存。镜像是保存当时系统盘的快照，后续新增或修改的文件不会自动更新到旧镜像中。

  • 镜像计费按账户全部镜像的总容量计算，30GB以内免费，超出部分为0.01元/GB/日。本镜像平台报告约13.75GB，是否收费还需合并其他镜像容量。
  • 镜像计费条款规定：账户连续3个月未登录，或欠费超过50元，平台保留删除数据的权利；并非达到条件必然立即删除。不要把平台镜像作为唯一长期备份。
  • Pro实例连续关机60天会被释放并清空实例数据；普通容器实例为15天。这是实例的数据保留周期，独立保存的镜像按镜像条款管理。
  • Pro关机后仍有系统盘费用，停止模型进程也不会停止GPU计费。长期不用时应先验证镜像和独立备份，再决定实例的保留方式。

依据：镜像文档、充值与计费中的镜像计费、Pro数据保留及磁盘计费。后续以官方最新条款与控制台为准。

应用备份：保持服务在线

本次新增的备份工具只读取白名单运行文件。创建期间不要升级依赖、修改源码或更新模型；它会核对前后文件状态，但这不是业务数据库的一致性快照。本服务的应用数据库、检索索引或外部媒体不在该归档内，业务系统须另做备份。

# 以下在 AutoDL 实例内执行；归档不要放进服务根目录
mkdir -p /root/omniembedding-backups
chmod 700 /root/omniembedding-backups
/root/omniembedding-service/.conda/bin/python \
  /root/omniembedding-service/scripts/autodl_backup.py create \
  --output /root/omniembedding-backups/embeddinggemma2-runtime.tar.gz

/root/omniembedding-service/.conda/bin/python \
  /root/omniembedding-service/scripts/autodl_backup.py verify \
  /root/omniembedding-backups/embeddinggemma2-runtime.tar.gz

工具会生成归档、SHA-256侧文件和逐文件manifest。务必另存一份到本机或你控制的对象存储；只把备份留在同一实例里，实例释放或账号不可用时仍然拿不到。HF缓存中的相对链接必须与 blobs 一起保留，不能只复制 model.safetensors。

更新平台系统镜像：安排维护窗口

  1. 先备份并校验当前环境，暂停新业务入队，等待已接受的任务完成。
  2. 通用官方镜像流程要求实例关机后保存。Pro保存API没有明确说明是否允许热保存，本轮没有冒险调用运行中的保存操作。
  3. 在控制台关机，选择“保存镜像”，写入包含模型revision与日期的版本名；等待镜像状态变成 finished。
  4. 开机后执行就绪、真实推理和公网验收，再恢复业务队列；新建实例要重新取得地址并配置6006映射与启动命令。
  5. 验证新版本后再考虑清理旧镜像；保留至少一个已知可恢复版本。
当前按量GPU不能保证随时可重新分配，之前已出现5090暂时无库存。保存镜像也不会锁定GPU库存。为了本次写指南和打包，无需关闭当前在线实例；最新平台系统快照仍待维护窗口。

4. 恢复、新建与离线验收

优先：从现有私有镜像新建

在AutoDL控制台从私有镜像选择上述image ID，选择兼容的NVIDIA GPU与驱动。当前环境是Linux x86_64、Ubuntu20.04、Python3.12、PyTorch2.11.0+cu128、torchvision0.26.0+cu128；调度驱动应支持CUDA12.8以上。私有镜像已有依赖和权重，直接启动即可。API创建时对应驱动下限 cuda_v_from:128、5090规格 5090-p；费用先核对，不要默认新规格也与当前单价相同。

旧平台镜像中还没有本次新增的ops/backup脚本；可上传这两个小文件再用下节命令，也可以直接使用镜像中已有runner。克隆实例会继承旧Key，按需要更换后启动。镜像中的旧PID文件不是进程存在的证明。

备用：从本次应用归档恢复

准备相容的Linux基础环境和NVIDIA驱动，上传归档与同名的 .manifest.json、.sha256 两个侧文件，单独上传 scripts/autodl_backup.py 作为恢复工具。基础系统的 python3（至少3.8）运行该工具；它使用标准库。目标必须严格为 /root/omniembedding-service 且尚不存在，工具拒绝覆盖任何现有部署。不要为通过检查而直接删除旧目录；确认停服后先把旧目录保留到别的位置。

# 在新的、兼容的 AutoDL/Linux 实例执行，先验证再恢复
python3 /root/autodl_backup.py verify \
  /root/omniembedding-backups/embeddinggemma2-runtime.tar.gz

python3 /root/autodl_backup.py restore \
  /root/omniembedding-backups/embeddinggemma2-runtime.tar.gz \
  --new-key

# 新Key只写入服务器 inference.key；用安全文件传输取得后更新调用方
/root/omniembedding-service/.conda/bin/python \
  /root/omniembedding-service/scripts/autodl_ops.py preflight

/root/omniembedding-service/.conda/bin/python \
  /root/omniembedding-service/scripts/autodl_ops.py start

归档不含服务Key；--new-key生成新Key且不显示内容。若需沿用原Key，不传该选项，启动前通过安全文件传输放回 inference.key 并设置600权限。恢复工具只恢复文件、不会启动服务或改变计费实例。

Conda环境有固定绝对前缀，归档按原目录恢复，不支持任意改目录。它不包含宿主机驱动或完整OS；不能拿到Mac/Windows直接运行，也不承诺不同glibc/架构可用。AutoDL当前不支持把这种应用tar包直接导入为自定义系统镜像。官方说明。

避免启动时访问下载站

本次已单独验证：已有缓存可在阻断外部socket连接的CPU进程中离线加载模型并生成一条文本向量；该检查没有重启线上GPU服务。下列离线入口适合缓存预检通过后的下一次计划启动。严格GPU冷启动、完整恢复及全部模态离线验收仍需维护窗口，不能用CPU检查替代。

# 显式离线启动；服务已在线时不会将现有进程切换成离线模式
/root/omniembedding-service/.conda/bin/python \
  /root/omniembedding-service/scripts/autodl_ops.py start --offline-start

该模式设置 HF_HUB_OFFLINE=1、TRANSFORMERS_OFFLINE=1、OMNI_AUTODL_NETWORK_TURBO=0。缓存缺失时应明确失败；不要自动退回下载或换模型。默认旧runner会初始化平台网络加速，且不默认强制离线。

5. 启动、停止、重启与开机自启

以下在AutoDL实例内执行；使用已有环境的绝对Python路径，不需要 conda activate，不需要AutoDL账户Token。新增工具核对PID、进程目录与监督锁，减少误杀旧PID或重复占用6006的风险。

cd /root/omniembedding-service

# 查看本机进程、监听与就绪摘要，不打印密钥
.conda/bin/python scripts/autodl_ops.py status

# 检查环境与本地模型缓存，不联网下载
.conda/bin/python scripts/autodl_ops.py preflight

# 后台启动已有runner；已在运行时不会叠加一个worker
.conda/bin/python scripts/autodl_ops.py start

# 计划停服：先暂停调用端队列，再停止监督与模型子进程
.conda/bin/python scripts/autodl_ops.py stop

# 查清故障或完成明确变更后重启；会短暂中断服务
.conda/bin/python scripts/autodl_ops.py restart

不要把这一条当成日常启动命令：bash scripts/autodl_bootstrap.sh。它属于安装入口，每次会进行16GiB空闲盘检查、调用pip安装和依赖检查、重写runner；相同依赖通常不会重下载，但缺失或变化仍可能联网，镜像恢复后也可能因空间预检被挡住。

无新增脚本时，直接启动旧runner

cd /root/omniembedding-service
mkdir -p logs run
nohup bash ./run-autodl.sh >> logs/supervisor.log 2>&1 < /dev/null &

runner用文件锁保证单监督进程；“发起启动”不等于模型已就绪。先确认HTTP开始监听，再运行完整验收。

平台开机命令

在控制台开机命令中填写下面内容；命令应使用原目录runner，不调用安装入口。现有部署记录显示曾配置开机命令，但本轮没有关机重启验证控制面配置是否仍生效。

cd /root/omniembedding-service && mkdir -p logs run && exec bash ./run-autodl.sh

下一次计划开机若使用Pro API，可在 POST /api/v1/dev/instance/pro/power_on 中显式传入该 start_command，并传 payload:"gpu"。其执行失败不会自动关闭计费实例，因此开机后必须验收。账户API使用原始开发者Token作为Authorization；它与推理接口的Bearer Key不同。官方Pro API。

停服或重启时先暂停业务接单并排空本地队列。监督进程收到TERM会结束子进程，最多等待15秒后强制结束仍存活子进程，因此可能中断在途长请求；不能把直接restart当作无损热切换。

6. 日常监控与故障处理

检查建议频率 / 行为它能说明什么
GET /health/live30–60秒；无需鉴权HTTP进程可响应；不能证明模型就绪。
GET /health/ready30秒，Bearer；连续3次失败再告警200 + ready=true + status=ok；检查model/revision/device/dtype/boot_id。不会实际跑模型。
POST /health/inference启动/恢复后，以及业务低谷每5分钟；纳入统一队列真实推理与768维、有限值和单位范数检查；占推理槽，忙时429不能直接认定模型故障。
调用端指标按1分钟窗口记录成功率、429、5xx、超时、排队时长、模型服务耗时和总延迟，按模态/批量/文本长度分别看。
资源 / 预算每分钟采样、每日核账；阈值是初始运维建议系统盘<20%提示、<10%告警；显存异常增长、监督退出、boot_id频繁变化、费用与余额异常需处理。
# 仅在服务器运维会话检查，日志按私有资料保存
tail -n 80 /root/omniembedding-service/logs/inference.log
tail -n 80 /root/omniembedding-service/logs/supervisor.log

现象处理顺序
401检查是否用了独立推理Key、Bearer头、文件600权限；修改Key文件后必须重启服务与更新客户端。不要拿账户JWT代替。
429 / Retry-After:2先看是否多个进程同时调用，统一实例级队列总在途设1；遵守等待并有界重试。不要先加worker或重启。
422 / 415 / 413 / 400核对下节真实协议、字段名、图片格式/帧数/像素/字节限制；修输入后再调用。禁止原样循环重试。
503 loading检查日志并等待模型加载，900秒是配置预算而非必然耗时。不要边加载边重复安装或启动多个服务。
503 degraded/stalled / OOM暂停任务，保留故障时间与日志摘要，检查显存与异常输入，等待监督恢复或确认后重启；重启后真实探针再放量。
公网超时 / 502，但本机ready通过查6006映射、当前公网域名、平台代理和网络；不要因此重装模型。客户端断开不保证GPU计算被取消。
本机6006无监听先看监督是否退出，再看日志、Key权限、缓存和磁盘；preflight通过后start。完整验证器遇TCP失败会直接失败，不能依赖其ready-timeout等待端口出现。
实例关机后无法开机查GPU库存与余额；镜像只能保环境、不能保证算力。换规格前确认兼容驱动与实时价格，用户允许上限¥8/小时。

本文给出监控频率与阈值建议，没有创建未来自动巡检或告警任务。应用现有ServiceHealth监控不是AutoDL实例电源开关。

7. 准确的调用接口

公网请求需HTTPS。除live外，使用 Authorization: Bearer <inference.key内容>。这是独立推理服务 omniembed.inference:create_app，不是带数据库、入库和检索的业务API。

路由请求返回
POST /v1/embeddingsapplication/json；input字符串或列表，input_type=query或document，dimensions可选，默认768；document可附等长titles每条文本一条向量；顺序由data[].index标识。
POST /v1/embeddings/image?dimensions=768multipart/form-data，单字段 file；JPEG/PNG/WebP静态图一张图一条向量。
POST /v1/embeddings/video?dimensions=768multipart/form-data，重复字段 files；1–8张同宽高、按时间顺序排列的静态帧整段帧序列一条向量；不是每帧一条。
{
  "input": ["锅中加入番茄与鸡蛋，快速翻炒。", "沿着海边步道观看日落。"],
  "input_type": "document",
  "titles": ["番茄炒蛋", "海滨日落"],
  "dimensions": 768
}

查询传 input_type:"query"，素材描述或正文入库传 document；前缀由服务自动添加，调用方传原文。query不能带titles，连 titles:null 也应省略。当前接口不接受 model、task、encoding_format 等额外字段，没有 /v1/models 或单数 /v1/embedding，也不使用 X-API-Key。不能直接照抄仓库业务API文档或假定完全兼容OpenAI SDK。

输入边界
文本每次最多16条；每条8192字符、每标题1024字符、整批正文+标题合计32768字符；JSON请求体最多262144字节。这里按字符限制，不等于模型的8192 token窗口。
图片单文件最多10MiB，最多16,000,000像素；不接受动图、URL或base64 JSON直传。
视频画面1–8帧，必须同宽高；总文件最多32MiB，总像素最多32,000,000。不要把MP4文件当file上传；当前不支持音频。
输出维度128 / 256 / 512 / 768。服务从原生768维截断后重新L2归一化；query、文档、图片与视频比较时必须使用相同模型版本、维度和预处理约定。

成功响应包含 model、model_revision、dimensions、boot_id 和 data:[{index,embedding}]。boot_id用于识别模型进程重启，不是机器ID，也不应作为业务内容缓存键。

8. 并发、批处理与高效检索

默认配置：实例级 max_inflight=1；在线查询优先，后台入库让出队列；文档批量先用8条、按长度分桶，再根据实际延迟尝试16条；默认768维。不要把更多HTTP并发等同于更多GPU吞吐。

服务只有一个GPU推理槽，推理锁忙时直接429，不在该锁上排队；HTTP接收、解码与线程池仍可能等待。示例客户端仅保证同一个对象串行；现有RemoteEncoder也只锁同一个适配器对象。多个进程、容器或客户端各自设并发1仍会互相碰撞。生产应让在线查询、批量入库、图片/视频与真实推理探针共用一个调度器。

场景建议设置实测依据 / 使用边界
在线短文本查询batch1；全局并发1；10–12QPS只作为灰度起点；设置有界队列、排队截止时间与超载拒绝固定约16字符模板的20秒测试；22RPS时虽然无429，实际吞吐约18.59/s，端到端p95约3.30s，说明请求已在客户端排队。
后台文档入库并发1，批量8–16，按长度分桶且满足整批字符/字节限制；查询到来后暂停发下一批1024字符文档batch16约68.67条/s；不能推成所有文本长度都最优。HTTP批量16，模型内部微批4。
图片 / 视频每次一图或一段帧序列，先统一尺寸；可从2–4帧试验，按任务质量需要增至8帧固定512×288 JPEG短窗口：图片11.71请求/s、2帧视频9.38/s、8帧视频5.94/s；不含下载、抽帧与完整业务链路。真实视频质量评测使用8帧，减少帧数前须复测召回。
混合在线流量按模态设置成本预算和队列；用实际混合比例重新测到达率单在途闭环30分钟，19,553次主请求均成功，约10.86请求/s；固定素材、无到达率积压，不代表10.86QPS通用SLA。
降低索引成本先保持768；对自有数据验收后考虑512512维裸float32向量少1/3，但COCO双向nDCG下降约0.57/0.80个百分点。维度缩小主要省存储/传输，不等比例省GPU推理；128维不建议默认。

短query并发2的原始压测出现约78.05%429，吞吐没有改善；加并发是在增加碰撞。队列也不能无限大，建议从最多8个待处理请求起步，并依据业务容忍的排队时间调整；超载应返回可解释的限流或稍后重试。重试总预算包含排队、网络和等待，避免每次尝试重新计满120秒。

把GPU花在真正需要重新编码的内容上

  • 入库增量化：缓存键包含内容哈希、model ID、revision、角色query/document、标题、输出维度；媒体还应包含缩放、抽帧时间戳与策略版本。相同内容不重复编码。
  • 查询不重复入库：文档、图片、视频向量先保存到索引；每次搜索只编码查询，再检索已有向量。单位向量可用内积进行余弦排序。
  • 长视频分段：按镜头或固定短片段建立向量，存source_id、起止时间和抽帧位置；不要用整部视频的8张帧代表所有内容。返回片段后再定位播放。
  • 调用与计算分开计量：分别记录排队、下载、抽帧、编码、索引检索与重排耗时。只优化HTTP延迟容易错过主要成本。
  • 需求超出单实例再扩容：持续队列积压时，可评估增加独立副本或实现并验证动态批处理；每个副本仍保留单推理槽。不要直接把当前uvicorn workers改为4，它会复制模型并破坏当前容量假设。

性能数字与限制来自已完成的系统评测。30分钟稳定性没有观察到重启或向量漂移，不代表24小时可用性承诺；中文图片/真实视频检索业务质量仍需自有样本验收。不要直接默认启用固定RRF融合，该组合在已测部分任务反而下降。

9. 接入现有应用与检索流程

当前OmniEmbedding业务服务

现有业务代码已有 RemoteEncoder，优先复用。为业务进程设置以下变量后重启业务进程，它会从独立Key文件读取并调用远端；它固定768维，不会自动退回本机下载模型。

unset OMNI_INFERENCE_URL  # 显式URL优先于endpoint.json；本段选择由文件提供地址
export OMNI_ENCODER_BACKEND=remote
export OMNI_MODEL=google/embeddinggemma-2
export OMNI_MODEL_REVISION=914f7f89142e33e77833254d9c9b90c3cef7303b
export OMNI_INFERENCE_ENDPOINT_FILE="$PWD/data/autodl/endpoint.json"
export OMNI_INFERENCE_KEY_FILE="$PWD/data/autodl/inference.key"
export OMNI_INFERENCE_TIMEOUT_S=120

这些是调用方配置；AutoDL上的推理进程继续用 OMNI_ENCODER_BACKEND=local 加载GPU模型。不要把远端服务也改成remote，否则可能形成错误的转发配置。业务系统的API Key与推理Key各司其职。

独立Python调用

此例使用第2节的环境变量；若执行过上一段的unset，请先重新设置 OMNI_INFERENCE_URL。

# 将 docs/examples/embeddinggemma_client.py 放到你的项目可导入位置
import asyncio, math, os
from embeddinggemma_client import EmbeddingGemmaClient, load_key

async def main():
    async with EmbeddingGemmaClient(os.environ['OMNI_INFERENCE_URL'], load_key()) as client:
        docs = await client.text(
            ['锅中翻炒番茄和鸡蛋。', '沿海岸步道观看日落。'],
            input_type='document', titles=['做饭', '海边'], dimensions=768)
        query = await client.text('厨房里做饭', input_type='query', dimensions=768)
        q = query['data'][0]['embedding']
        ranked = sorted(
            [(r['index'], math.fsum(x*y for x, y in zip(q, r['embedding'])))
             for r in docs['data']], key=lambda x: x[1], reverse=True)
        print(ranked)  # 示例仅2条；生产请预先入库并使用向量索引

asyncio.run(main())

图文检索：图片用image接口入库，文本query查询；视频检索：每个片段用video接口入库，文本query查询。图搜图可比较两边image向量。更换模型revision、向量维度或重要预处理时，新建索引版本并全量或增量重建；不要把新旧向量混到一个无版本字段的集合中。

10. 密钥管理与版本升级

推理服务只需要独立服务Key，正常启动与请求都不需要AutoDL开发者Token。Token只供控制面开关机、镜像和资源管理；不要放进runner、客户端源码、镜像中的shell历史或调用日志。不要公开分享包含Key的系统镜像。

本次应用归档排除了凭据；系统镜像会保留盘上Key。新建副本若要隔离权限，创建新Key后重启整个监督进程，使内存中的鉴权值更新；再以安全文件传输更新调用端文件，验证新Key可用、旧Key返回401。只修改磁盘文件不会立即改变当前服务进程的Key。长期使用的httpx示例客户端也应重新创建；RemoteEncoder会在每次请求重读Key文件。

# 维护窗口内操作：先排空业务队列；任一步失败即停止后续操作
set -e
cd /root/omniembedding-service
.conda/bin/python scripts/autodl_ops.py stop
.conda/bin/python - <<'PY'
import os, secrets
from pathlib import Path
p = Path('inference.key.next')
with os.fdopen(os.open(p, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600), 'w') as f:
    f.write(secrets.token_urlsafe(48) + '\n')
os.replace(p, Path('inference.key'))
PY
.conda/bin/python scripts/autodl_ops.py start
